# 伤痛档案 — 实施计划

> 目标：让用户自主提交攀岩受伤经历，通过真实案例帮助社区了解常见伤害、提高安全意识、学习预防方法。

---

## 一、功能定位

这不是一个开放讨论的社区，而是一个**结构化的伤害案例征集表单**。用户按照引导逐步填写受伤经历，最终汇总为一个可浏览、可筛选的案例库。核心价值是"前车之鉴"——让还没受过伤的人看到真实案例后更加注意安全。

**正式名称**：伤痛档案（英文：Injury Archive）

## 二、站内入口与导航

### Header 顶部导航

在 Header 中增加三个顶级快捷按钮，代表网站的三大板块：

| 按钮 | 路由 | 说明 |
|------|------|------|
| 知识库 | `/` | 现有的知识库首页 |
| 名人堂 | `/hall-of-fame` | 现有的攀岩名人堂 |
| 伤痛档案 | `/injuries` | 新增的伤害案例板块 |

三个按钮紧跟在 Logo 右侧（桌面端）或收进汉堡菜单（移动端），当前所在板块高亮显示。

### 侧边栏导航

在"攀岩名人堂"下方新增一项"伤痛档案"，与名人堂同级，使用区分度高的图标（如 alert-triangle 或 heart-pulse）。

### 首页入口卡片

在名人堂卡片下方新增一个入口卡片，采用偏暖色调（橙/红），与名人堂的金色调形成区分：
- 标题："伤痛档案"
- 副标题："来自真实攀岩者的受伤经历——了解风险，做好预防"
- 右侧引导文字："查看档案 →"

## 三、用户注册与登录

### 注册/登录方式

目前使用邮箱 + 密码登录（后续可扩展 Google 登录供海外用户使用）。

### 页面设计

提供一个统一的注册/登录页面（`/auth`），包含两个 Tab 切换："注册"和"登录"。

**注册表单：**
- 邮箱（必填）
- 密码（必填，至少 6 位）
- 昵称（必填，注册时设置，之后可修改）

**登录表单：**
- 邮箱
- 密码
- "忘记密码？"链接（Supabase 内置密码重置邮件）

### 登录引导时机

用户可以自由浏览伤痛档案列表和详情，**不需要登录**。只有在以下操作时才提示登录：
- 点击"提交我的经历"按钮时
- 尝试点赞或评论时

未登录用户点击这些操作时，弹出登录/注册弹窗（Modal），而不是跳转页面，完成后自动回到原来的位置。

### 个人设置

登录后 Header 右侧显示用户头像/昵称，点击展开下拉菜单：
- 我的提交（查看自己提交的案例）
- 修改昵称
- 修改密码
- 退出登录

## 四、用户提交的字段设计

### 必填项

| 字段 | 说明 | 输入方式 |
|------|------|---------|
| 受伤部位 | 手指、手腕、肩膀、膝盖、脚踝、背部、肘部、其他 | 多选 + 自定义输入 |
| 受伤类型 | 拉伤、扭伤、骨折、滑囊炎、肌腱炎、脱臼、皮肤撕裂、其他 | 单选 + 自定义输入 |
| 受伤经过 | 当时发生了什么？怎么受伤的？ | 文本框（最少 20 字） |
| 自己认为的原因 | 当时觉得可能是什么导致了受伤 | 文本框 |
| 攀岩类型 | 抱石 / 运动攀 / 传统攀 / 顶绳 / 室内 | 单选 |

### 攀岩背景（必填）

| 字段 | 说明 | 输入方式 |
|------|------|---------|
| 日常水平 | 平时爬的难度等级 | 下拉选择（V0–V16 / 5.6–5.15d） |
| 受伤时难度 | 受伤那次爬的是什么难度 | 下拉选择 |
| 攀岩年限 | 已经攀岩多久了 | 下拉选择（< 6个月 / 6–12个月 / 1–2年 / 2–5年 / 5年以上） |
| 攀岩频率 | 每周大概爬几次 | 下拉选择（1次 / 2–3次 / 4–5次 / 6次以上） |

### 选填项（鼓励填写）

| 字段 | 说明 | 输入方式 |
|------|------|---------|
| 受伤前是否热身 | 受伤那次有没有做热身 | 是 / 否 / 不记得 |
| 是否在疲劳状态 | 当时是不是已经爬了很久、很累了 | 是 / 否 / 不确定 |
| 是否就医 | 有没有去看医生 | 是 / 否 |
| 诊断结果 | 医生怎么说的 | 文本框 |
| 恢复时长 | 花了多久恢复 | 下拉选择（< 1周 / 1–4周 / 1–3个月 / 3–6个月 / 6个月以上 / 至今未完全恢复） |
| 给他人的建议 | 经历这次受伤后，你想提醒其他攀岩者什么？ | 文本框 |
| 受伤照片/视频 | 如果愿意的话上传照片或视频 | 图片/视频上传（合计最多 5 个文件） |

### 媒体上传规则

- 支持照片和视频混传，总数上限 **5 个文件**
- 所有提交内容**默认公开**，不设"是否同意公开"选项（不公开则无分享意义，提交前页面会明确告知）

### 用户信息

- 不需要真实姓名，使用**昵称**展示
- 用户可以随时在个人设置中**修改昵称**
- 不需要精确日期（只需大概时间段）
- 不收集医疗病历或隐私信息

## 五、浏览端设计

### 案例列表页（`/injuries`）

- 卡片式展示，每张卡片包含：受伤部位标签、攀岩类型、难度等级、简短摘要
- 筛选器：按受伤部位、攀岩类型、难度范围、攀岩年限
- 排序：最新提交 / 最多浏览
- 顶部统计栏：总提交数、最常见受伤部位 Top 3、受伤高发难度区间

### 案例详情页（`/community/injuries/:id`）

- 完整的受伤经过描述
- 受伤照片（如有）
- 攀岩背景信息卡片
- "给他人的建议" 高亮展示
- 关联的知识点标签（如 kp-warm-up、kp-finger-strength 等）

### 数据洞察页（可选，后期）

- 受伤部位分布饼图
- 攀岩年限 vs 受伤类型的交叉分析
- "是否热身" 与受伤比例的对比
- 难度超出日常水平的比例统计

## 六、与现有知识库的联动

- 每个伤害案例可以关联到知识库中的知识点（通过 `post_knowledge_points` 表）
- 例如：一个手指滑囊受伤的案例可以关联到 "握法类型"、"热身方法"、"手指训练" 等知识点
- 在知识点详情页中，可以展示"相关伤害案例"板块，形成双向链接
- 这样用户在学习某个技术时，能同时看到"做不好会怎样"的真实反面案例

## 七、数据库扩展

在现有 `posts` 表基础上，新增一张 `injury_details` 表存放伤害特有的结构化字段：

```sql
CREATE TABLE IF NOT EXISTS injury_details (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  post_id UUID NOT NULL UNIQUE REFERENCES posts(id) ON DELETE CASCADE,

  -- 受伤信息
  body_parts TEXT[] NOT NULL,          -- 受伤部位（数组，可多选）
  injury_type TEXT NOT NULL,           -- 受伤类型
  injury_cause TEXT,                   -- 自己认为的原因

  -- 攀岩背景
  climbing_type TEXT NOT NULL,         -- 抱石 / 运动攀 / 传统攀 / 顶绳 / 室内
  usual_grade TEXT,                    -- 日常水平
  injury_grade TEXT,                   -- 受伤时难度
  climbing_experience TEXT,            -- 攀岩年限
  climbing_frequency TEXT,             -- 每周频率

  -- 受伤上下文
  did_warm_up TEXT,                    -- 是否热身：yes / no / unsure
  was_fatigued TEXT,                   -- 是否疲劳：yes / no / unsure
  sought_medical BOOLEAN,             -- 是否就医
  diagnosis TEXT,                      -- 诊断结果
  recovery_duration TEXT,              -- 恢复时长

  -- 经验分享
  advice_to_others TEXT,              -- 给他人的建议

  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

这样 `posts` 表负责通用字段（标题、描述、图片、评论、点赞），`injury_details` 表存放伤害案例的结构化数据，通过 `post_id` 一对一关联。

## 八、实施步骤

### Phase 1 — 基础框架 + 用户系统（MVP）

1. Header 导航改造：增加"知识库 / 名人堂 / 伤痛档案"三个顶级按钮
2. 侧边栏新增"伤痛档案"入口
3. 首页新增伤痛档案入口卡片
4. 注册/登录页面（`/auth`）：邮箱+密码注册、登录、忘记密码
5. Header 登录状态展示：未登录显示"登录"按钮，已登录显示头像/昵称下拉菜单
6. 个人设置功能：修改昵称、修改密码
7. 创建 `injury_details` 数据表 + RLS 策略
8. 开发提交表单页面（`/injuries/new`），未登录时引导登录
9. 开发案例列表页（`/injuries`）
10. 开发案例详情页（`/injuries/:id`）
11. 基础筛选功能（按受伤部位、攀岩类型）

### Phase 2 — 丰富体验

12. 媒体上传支持（照片/视频，合计最多 5 个）
13. 知识点关联（提交时可选择相关知识点）
14. 知识点详情页展示"相关伤害案例"
15. 顶部统计栏
16. "我的提交"页面

### Phase 3 — 数据洞察（可选）

17. 受伤数据可视化图表
18. 交叉分析（年限 vs 伤害类型、热身 vs 受伤率等）
19. 匿名数据导出（供研究使用）

## 九、内容审核

- 提交后默认公开，但提供举报按钮
- 管理员可在 Supabase Dashboard 中直接查看和删除不当内容
- 后期如果量大，考虑加审核队列

## 十、注意事项

- 页面顶部需要声明：本页面内容为用户自述经历，不构成医学建议，受伤后请及时就医
- 表单提交前提示用户：提交即表示同意公开展示（可匿名）
- 保护用户隐私：不强制上传照片、不收集真实姓名
- 考虑敏感内容：受伤照片可能令人不适，展示时需要做模糊处理 + 点击后查看
